4. SEC/기업 공시, OECD/FAO에서 재확인한 사실만 `VERIFIED_PRIMARY`, 장비 AI 수치는 `COMPANY_CLAIM`, 과거 대화 수치는 `PREVIOUS_CHAT`, 추론은 `HYPOTHESIS` 등으로 표시.
5. 현 주가·재무·상장 상태·실적 발표는 시간이 지나면 무효. 이전 PM의 `2026-11-15` 스냅샷을 '현재'로 재사용 금지.

## 분석 단위 / 기록 원장
- `CURRENT_STATE`: 현재 단일 핵심 과제·진입 제한·검증 수준만. 상세 근거 중복 복사 금지.
- `THESIS_AND_MARKET`: 가설, 표준 분모와 소비자 경제성 산식, 기술 비교 정의; 회사별 최신 숫자는 COMPANIES로.
- `COMPANIES`: 기업 단위 사업/해자/위험/희석/후속. 이미 확정된 내역은 덮어쓰지 않고 재정의 시 날짜와 상호 링크.
- `EVIDENCE_INDEX`: 1개 주장당 공식 원문·공시일·근거 수준; 자료 불일치 시 충돌 양쪽 보존.
- `DECISIONS`: Owner 명시 결정만 Owner 레벨, PM의 가설과 엄격히 구분.
- `ROADMAP`: 연구 단계와 종료 게이트; 진행 중에 새 범위 무단 생성 금지.
- `NEXT_ACTION`: 후속 단일 최우선 작업, 가드·보고 형식·종료 조건.

## 독립 감사
- 기업 발표 40~50% 인력/원가 절감 같은 표현은 **설비 전체인지 특정 공정인지**, 평균인지 단일 사례인지, 부품 원가인지 매출총이익인지, 개발/시운전 단계인지 검증.
- 비슷한 용어의 분모 차이를 통과시키지 말 것: `장비 주문 비중 vs 전체 매출`, `Protein 부문 매출 vs poultry 매출`, `원유 투입량 vs 완제품 원가`, `FCR 생체중 vs 단백질 실소매가격`, `GAAP EPS vs adjusted EPS`, `전사 매출 vs 자회사 사업 매출`, `성장률 vs 주가 수익률`.
- 소매 가격 비교는 동일 국가/주간 가격/가식부/원물/냉동·신선/조리수율을 일치시켜 독립 재현. 서로 다른 시대의 소매 광고 가격을 그대로 비교하지 말 것.
- 주식 비교에는 반드시 동일한 시점/통화/주식수/부채/환율과 회계기간 적용. 미래 예상은 사실이 아니라 가정/확률.
- 중국/유럽 대조군은 Owner가 선호한 미국 상장 제한을 변경하지 않음. 미국 OTC 외국기업도 미국 기업과 혼동 금지.

## 2026-11-19 Owner 최신 필수 규칙 — 결론 우선 통합 보고서·최소 갱신

1. **매 투자 논의 끝에 정리·저장:** 중대한 새 질문/가설, 기술·사업 수치, 기존 결론의 변화, 반론·검증 과제를 **관련 정본에 업데이트**. 실질적 변화가 없으면 "신규 기록 없음"을 밝히되 불필요한 커밋은 하지 않는다.
2. **두괄식·압축:** 결론 → 3개 이내 핵심 근거/비교 수치(같은 기간·분모) → 최대 반론 → `UNKNOWN/HOLD` → 다음 투자판단 조건. 같은 사실/설명은 보고서의 정확히 한 곳에서만 설명하며 다른 위치에는 링크/짧은 요약만.
3. **중복·누락 감사:** 사용자 자료 전체를 읽되 **원문 전문을 GitHub에 무조건 복제하지 않는다**. 주요 독립 질문·기업·테마별로 기존 정본에 충분한 기록이 있는지 점검. 신규 단편 보고서 다량 생성 금지. 과거 답변 숫자/이벤트는 `PREVIOUS_CHAT`, Owner 주장 vs PM 결론 vs 공식 검증 구분.
4. **변경 최소화:** 최신 정본 해당 섹션, `CURRENT_STATE`, `NEXT_ACTION` 중심. 새 Owner 확정 결정 발생 시에만 `DECISIONS`에 ID 추가, 공식 1차 근거가 생길 때 `EVIDENCE_INDEX` 갱신, 새 주제일 때 `README` 인덱스 수정. 각 턴마다 5~8개 파일을 기계적으로 복제/갱신하지 말 것.
5. **검증/결과 보고:** commit SHA, 변경 파일과 핵심 판정, GitHub `fetch_file` 재조회 확인 후에만 `반영 완료`라고 보고. 반영 실패 시 미반영 상태/원인 보고. 자동 백그라운드 업로드를 약속하지 않는다.
